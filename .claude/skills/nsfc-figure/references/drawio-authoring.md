# Draw.io 图示设计与验证

本参考用于决定技术路线图的版式和交付检查。它总结的是通用图形原则，不应替代对申请书正文的事实核对。

## 先选关系，再选形状

| 主要关系 | 推荐布局 | 不宜使用的情况 |
|---|---|---|
| 阶段递进 | 左到右或上到下的单向路线 | 多项内容相互独立且没有先后关系 |
| 并行支撑 | 同宽分栏，底部汇聚到共同目标 | 正文明确要求逐阶段完成 |
| 多尺度/多层级 | 上层问题、中层研究内容、下层证据或产出 | 仅仅为了把所有名词放进一张图 |
| 反馈迭代 | 主路径清晰、反馈线使用次要虚线 | 正文没有实验—模型或预测—验证反馈 |
| 年度安排 | 甘特图或任务—年份矩阵 | 表达机制、依赖和科学问题 |

一张图只承担一个主关系。若需要同时说明科学问题、研究内容、技术路线和年度计划，拆成多张图通常更清楚。

## 生成器输入 schema

`scripts/generate_roadmap.py` 接收一个 JSON 对象：

| 字段 | 类型与约束 | 用途 |
|---|---|---|
| `title` | 非空字符串 | 图的主标题 |
| `subtitle` | 非空字符串 | 一行逻辑摘要 |
| `stages` | 2–4 个对象 | 研究阶段或并列内容；四阶段会自动使用更宽画布 |
| `stages[].title` | 非空字符串 | 阶段短标题 |
| `stages[].summary` | 非空字符串 | 该阶段要解决的问题或目标 |
| `stages[].tasks` | 1–4 个对象 | 每项包含非空的 `title` 和 `detail` |
| `stages[].output` | 非空字符串 | 可核验的阶段产出 |
| `stages[].color` | 可选 `#RRGGBB` | 阶段强调色；省略时使用内置语义色 |
| `final_outcome` | 非空字符串 | 各阶段汇聚的综合目标 |

三栏时任务说明宜控制在约 45 个中文字符内，四栏时宜控制在约 35 个字符内；超出后应导出检查并手工增大卡片，而不是依赖 `overflow=hidden`。模板见 `assets/three-stage-roadmap.json`，四阶段只需按同一结构增加一个 `stages` 对象。

## 通用视觉系统

- 使用“标题卡 + 内容分组 + 卡片 + 汇聚结果”的层级。标题说明图的结论，分组表示阶段或研究内容，卡片承载动作与产物。
- 同级分组使用相同宽度、内边距和圆角。白色卡片放在低饱和度浅色分组背景上，边框使用对应强调色。
- 推荐每张图使用一个中性色和不超过四个语义强调色。强调色可采用橙 `#E67E22`、绿 `#2E9D50`、蓝 `#2F80ED`、紫 `#8E5CC7`；不要依赖颜色单独表达含义。
- 中文优先使用可替换的无衬线字体，例如微软雅黑或思源黑体；英文和数字可使用 Arial。申请书实际插图宽度下，正文建议不小于 8 pt。
- 卡片采用“短标题 + 一句说明”。同一层级的动词形式保持一致，例如均使用“构建、解析、验证”，或均使用名词短语。
- 主流程箭头使用实线，反馈或证据汇聚使用较浅的虚线。减少折点，禁止用无意义双向箭头掩盖依赖不清。

## Draw.io XML 约定

- 推荐未压缩结构：`mxfile > diagram > mxGraphModel > root > mxCell`。它比压缩字符串更适合审查、合并和自动验证。
- `0` 是根单元，`1` 是默认图层；普通节点和边通常以 `1` 为 `parent`。
- 每个可见节点需要 `vertex="1"` 和包含 `x/y/width/height` 的 `mxGeometry`。
- 每条连接线需要 `edge="1"`、有效的 `source/target`，以及 `relative="1"` 的 `mxGeometry`。
- 文本使用 `html=1;whiteSpace=wrap;` 时，先对用户内容做 HTML 转义。不要把未经处理的正文拼接进 XML。
- 外部图片若使用 `file:///...` 等本机路径，换机器后会丢失。优先嵌入或在交付包中使用明确的相对资源。
- `.drawio` 可能保留隐藏图层、画布外对象和旧文本；正式交付前既要看渲染结果，也要审查全部单元。涉及机密申请书时使用本地编辑器，除非用户明确授权，否则不要把源文件上传到在线转换服务。

## 导出与视觉检查

使用官方 Draw.io Desktop CLI 导出；不同版本的参数可能略有差异，应先运行 `drawio --help`：

```bash
drawio --export --format svg \
  --output roadmap.svg roadmap.drawio

drawio --export --format pdf --crop \
  --output roadmap.pdf roadmap.drawio

drawio --export --format png --scale 2 --border 20 \
  --output roadmap.png roadmap.drawio
```

`--embed-diagram` 会把完整可编辑源嵌入 SVG/PNG，适合受控的内部协作，不适合作为默认提交产物。公开或提交前应确认导出文件不含 `mxfile` 编辑数据及不必要的作者、路径或软件元数据，同时把私有 `.drawio` 源文件单独保存。

对 SVG/PNG 可运行：

```bash
python nsfc-figure/scripts/check_export_metadata.py roadmap.svg roadmap.png
```

脚本返回非零状态表示检测到内嵌编辑源、文件损坏或不支持的格式。它只报告元数据键，不打印元数据内容，以免检查日志再次泄露文本。

导出后必须实际打开文件检查；命令返回成功不代表图可以直接使用：

1. 页面没有被裁切，卡片文字没有溢出或被省略。
2. 字体替换后没有改变断行和卡片高度。
3. 连接线没有穿过文本，主阅读路径不需要猜测。
4. SVG/PDF 在申请书实际宽度下仍清晰；必须使用 PNG 时再按最终物理尺寸导出至少 300 DPI。
5. 图中术语、编号、箭头方向和正文逐项一致。

`scripts/validate_drawio.py` 只能证明 XML 和图结构满足基本不变量，不能证明版式美观，也不能代替上述视觉检查。
